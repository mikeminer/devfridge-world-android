## Additional packaging issue found during this review

The published **0.3.2-beta.1 / versionCode 8** APK includes three exported AndroidX instrumentation helper activities even though the app's own share-receipt activity is correctly confined to `androidTest`. This was discovered by inspecting the *merged release manifest and actual APK*, rather than assuming that every test helper disappears from release.

Gradle's offline `releaseRuntimeClasspath` dependency insight gives the exact chain:

```text
com.solanamobile:mobile-wallet-adapter-clientlib-ktx:2.0.7
  → androidx.test.ext:junit-ktx:1.2.1 [published runtime dependency]
    → androidx.test.ext:junit:1.2.1
      → androidx.test:core:1.6.1
```

Test core's manifest contributes `InstrumentationActivityInvoker$BootstrapActivity`, `$EmptyActivity` and `$EmptyFloatingActivity`, each exported, along with `REORDER_TASKS`. Their presence is unnecessary release surface. No exploit, private-key exposure or wallet transaction through them was demonstrated.

**0.3.2-beta.2 / versionCode 9**, source commit [`f2408f43af4446bcd082c93574f14c6f24eb3af6`](https://github.com/mikeminer/devfridge-world-android/commit/f2408f43af4446bcd082c93574f14c6f24eb3af6), adds only a release manifest overlay, `android/app/src/release/AndroidManifest.xml`, with `tools:node="remove"` for those three exact activity names. It leaves the MWA SDK dependency classes intact and keeps debug/androidTest helpers available. It does not remove launcher/deep-link support, change authorization, change the engine or relax access checks. `REORDER_TASKS` remains; this change does not remove the entire test dependency tree.

Lint initially reported `MissingClass` for the three removal-only nodes. `tools:ignore="MissingClass"` is scoped to those exact markers, with a comment explaining the removed declarations. No shipping class check or wider lint category was disabled. The merged manifest and AAPT2 inspection independently verify that no corresponding activity declaration remains.
